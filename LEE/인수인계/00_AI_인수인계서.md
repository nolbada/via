## 3. 앱 구조와 확정된 결정들

### 기술
- 순수 JS 한 페이지 앱(프레임워크 없음). 해시 라우팅: `#home`, `#p/<id>/<탭>[/<번호>]`. 지문 데이터는 `<script>` 로 지연 로딩(`window.MG[id]`), 어휘는 `VOCADATA`, 동사형은 `VERBDATA`.
- 지문 한 개의 탭: 1 본문+내용이해(막별 흐름·직독직해·막히는 문장 별표), 2 어휘 함정 피하기, 3 문법 포인트, f 시험 직전 마무리(파이널 주간), 4 동사형 말하기 시험.
- 지문 1개 "타파" = 탭 1·2·3 모두 체크(교과서·학교 수업 지문). 일반 모의고사 지문은 탭 1·2만. 파이널(f)과 동사형(4)은 타파에 포함하지 않는다.
- 학생 진행 기록은 기기 localStorage(`mogo26-h2-v2`)에 저장. 기기 간 이동은 "기록 코드(M2.…)"로 한다. 서버를 켜면 이름+번호로 자동 저장·불러오기가 된다.

## 4. 새 지문 만드는 방법 (26년 10월 추가용)

1. `gen/SPEC.md` 를 읽는다(구조·절대 규칙·유형별 지침이 다 있다).
2. 원문·한국어 해석을 `gen/src_2610.json` 으로 만든다(기존 `src_2410.json` 과 같은 구조: 문항 번호 키 -> sents[{en,ko}]). 각 지문 JSON 에 `"srcfile":"src_2610.json"` 을 넣어 원문 파일을 지정한다(교과서 지문이 이렇게 한다. build.py 의 `src_for` 참고). 아잉카 분석 텍스트는 `gen/src/ayinka_NN.txt`, 메타는 `gen/src/meta_*.json`. 이 원자료들은 선생님(들)이 가진 아잉카·이그잼포유 분석지에서 추출한 것이다. 26년 10월 자료는 선생님께 파일을 받아야 한다.
3. 어휘 후보는 `gen/cand.py` 를 참고해 `lex.json` 에 있는 짝만 쓴다.
4. 지문 JSON 은 `gen/data/<id>.json` 한 개씩. `python3 validate.py data/<id>.json` 이 OK 가 될 때까지 고친다.
5. `python3 build.py` 로 `app/` 의 data, voca/data, verb/data, manifest 를 다시 만든다.
6. 26년 10월을 위해 코드 수정이 필요한 곳(아직 안 했음, 반드시 확인):
   - `gen/build.py`: 그룹 매핑 `{2024:'g2410',2023:'g23',2022:'g22'}` 에 2026(`g2610`) 추가. 같은 파일 아래쪽 "planned placeholders" 부분과 `ready` 처리 확인.
   - `app/app.js` 의 26년 10월 자리표시(`g2610-1`~`10`)는 실제 지문이 매니페스트에 들어오면 중복되지 않도록 제거하거나 id 규칙을 맞춘다. 실제 문항 번호를 id 로 쓸지(`2610-29` 식) 자리표시 번호(1~10)를 쓸지 정한 뒤 `GSHORT`, `SLOTS`, `ofGroup` 정렬이 맞는지 확인한다.
   - `SLOTS` 는 기록 코드 칸 배치다. `['g2610',1,8]` 은 8칸뿐이므로 10개를 쓰려면 칸을 늘려야 하는데, 이는 기록 코드 형식이 바뀌어 기존 코드와 어긋난다. 학생이 코드를 많이 쓰기 전에 한 번에 바꾸거나, 서버 자동 저장만 쓰도록 안내한다.
7. 로컬에서 시험(7번)한 뒤 배포한다.

- 현재 저장소는 Julia 선생님 계정(`nolbada`) 소유다. 남편 쪽 AI가 푸시하려면 (a) 남편 계정을 저장소 협력자(Collaborator)로 초대하거나, (b) 남편 계정으로 새 저장소를 만들어 `app/` 을 올리고 GitHub Pages 를 켜는 방법이 있다. 서버 로그인을 켜 지문 파일을 저장소에서 빼야 하므로 (b)가 더 깔끔하다(옛 기록에 지문 파일이 남아 있는 저장소를 피할 수 있다). 선생님과 상의해 정한다.
- 이 앱을 만든 쪽은 로그인된 브라우저에서 파일을 올리는 방식(웹 업로드)을 썼다. 새 환경에서는 git 명령(토큰 인증)이 더 편하다. Pages 반영은 푸시 후 몇 분 걸린다.
- 비밀번호·토큰은 이 폴더에 없다. 선생님이 직접 로그인한다.

### 6-2. 서버 로그인(학생별 열람 차단) 켜기
목적: 학생이 그만두면 그 학생만 자료를 못 열게 하기. 같은 앱 하나로 가능하다. 구현은 끝났고(`app/gate.js`, `server/gas-server.gs`, `app/app.js` 의 GATE 분기) 가짜 서버로 시험을 마쳤으나 실제 구글 서버에는 아직 배포하지 않았다. 현재 `app/sync.js` 에서 `MOGO_GATE=0` 이라 꺼져 있다.
원리: 지문 데이터를 공개 파일에서 빼서 구글 시트(Apps Script)에 두고, 이름+번호 4자리로 로그인했을 때만 내려준다. 시트의 [학생] 탭에서 상태를 "퇴원"으로 바꾸면 그 학생은 다음 접속부터 열리지 않는다. 이미 화면에 열린 내용의 캡처는 막을 수 없다.
선생님이 직접 할 일(안내해 주기):
1. 남편 구글 계정으로 새 구글 시트를 만든다.
2. 확장 프로그램 > Apps Script 에 `server/gas-server.gs` 전체를 붙여넣고, 맨 위 `ADMIN_KEY` 를 선생님만 아는 긴 문자열로 바꾼다(AI에게 알려 줘도 되나, 채팅에 남기지 않는 게 좋다).
3. 배포 > 새 배포 > 유형 "웹 앱" > 실행: 나 / 액세스: 모든 사용자 > 배포. 나온 웹 앱 주소(`https://script.google.com/macros/s/.../exec`)를 AI에게 준다. 코드를 고치면 "배포 관리 > 편집 > 새 버전"으로 다시 배포해야 반영된다.
4. 시트에 [학생] 탭이 자동으로 생기면 이름 | 번호(4자리) | 상태(재원/퇴원) | 반 을 적는다. 번호 열은 텍스트 형식(앞자리 0이 사라지지 않게).
AI가 할 일:
5. `server/seed.html` 을 선생님 컴퓨터에서 열어 `app/data`, `app/voca/data`, `app/verb/data` 의 지문 파일을 시트 [자료] 탭에 올리게 한다(주소·관리자 키 입력 -> 폴더 선택 -> 올리기 -> "서버에 올라간 자료 확인"으로 빠진 것 0 확인). `manifest.js` 는 공개 파일이라 올리지 않는다.
6. `app/sync.js` 를 `MOGO_SYNC="<웹앱 주소>"`, `MOGO_GATE=1` 로 바꾼다. 같은 주소로 진도 자동 저장도 쓴다(`MOGO_SCOPE` 는 시트 탭 이름).
7. 실제 학생 한 명(시험용 학생 1명)으로 로그인·지문 열기·퇴원 처리 시험. 한 명을 "퇴원"으로 바꿔도 다른 학생이 정상인지 확인.
8. 확인된 뒤에만 공개 저장소에서 `data/*.js`, `voca/data/*.js`, `verb/data/*.js` 의 지문 파일을 삭제한다(`manifest.js` 는 남김). 단 GitHub 기록(history)에는 옛 파일이 남는다. 완전히 막으려면 껍데기만 올린 새 저장소를 쓴다(6-0).
한계/남은 결정:
- 목록(manifest.js)의 지문 제목·주제는 공개로 남는다.
- "진도 순서 잠금"(앞 지문을 끝내야 다음이 열림)은 선생님이 원했지만 규칙이 정해지지 않아 구현하지 않았다. 원하는 규칙을 선생님께 묻는다.
- 같은 이름 학생이 있으면 이름 뒤에 B 등을 붙여 구분한다. 번호 틀리기 10회면 15분 잠긴다.

## 7. 개발·시험 방법

- 로컬 실행: `app/` 에서 `python3 -m http.server 8799` 후 `http://localhost:8799/index.html`. 다른 포트가 이전에 열려 있으면 오래된 서버를 만날 수 있으니 새 포트를 쓴다.
- 자동 시험: Playwright(Chromium)로 화면을 열어 확인했다(스모크 시험 + 화면 캡처). 날짜 의존 기능(밀린 숙제·검사)은 `Date` 를 가짜로 바꿔 시험한다.
- 서버 시험: 가짜 서버 시험 도구(gatemock.py, gatetest.py)는 학생 이름이 들어 있어 이 보관본에는 없고 zip 묶음에만 있다.
- 지문 데이터를 고친 뒤에는 `gen/build.py` 로 다시 만든다. 이 폴더의 `gen/` + `app/` 으로 `build.py` 를 돌리면 `app/` 의 지문 파일 42개가 현재 것과 똑같이 재생성되는 것을 확인했다(경로는 상대경로로 고쳐 둠).
- 셸에서 `pkill -f` 같은 광범위 종료 명령은 쓰지 않는다(세션이 죽은 적이 있다).

## 8. 선생님 요청 이력 (결정 배경)

- 진도표 첫 화면은 플래너. 어떤 학생은 지문별로 타파하고 싶어 하므로 "범위별로" 탭을 둠(트리: 범위 -> 지문). "동사형 시험 대비" 탭은 따로.
- 타파 개수: D-day 밑에 "n/전체 타파"로 긴장감을 주되 파이널 마무리는 제외.
- 마무리를 "파이널 주간"으로 명시: 학생이 그것까지 미리 타파하려 하지 않도록.
- 서버 열람 방식을 선생님이 직접 선택함: "이름+번호로 서버에서 열어주기".
- 말하기 검사: 선생님과 검사받았으면 체크하는 항목, 6주 안에 몇 개씩인지 산술 계산, 평소 체크와 다른 색, 항상 공부 먼저 -> 검사 순서(릴레이), 밀린 정도 표시.
- 지문 순서: 교과서 -> 24 -> 26 -> 23 -> 22 로 확정.
- 제목에 학생 이름, 홈 탭 3개 색 구분(기능이 있는지 학생이 알아보게).
- 학생에게 보이는 분석 출처 문구는 "아잉카 · 이그잼포유 분석 종합" 한 줄(오답률·유형 표시 삭제).

## 9. 주의

- 이 자료에는 학원의 분석지에서 추출한 텍스트(`gen/src*`)가 들어 있다. 공개 저장소에 올리지 말고 이 폴더 밖으로 퍼뜨리지 않는다.
- `server/seed.html` 은 관리자 키를 입력하는 화면이다. 공개 저장소에 올리지 않는다. 관리자 키는 어떤 파일에도 저장하지 않는다.
- 학생 이름·번호를 코드나 저장소에 넣지 않는다(시트에서만 관리).
