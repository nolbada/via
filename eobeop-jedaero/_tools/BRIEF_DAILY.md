# 어법제대로 변형 해설을 "데일리어법" 방식으로 다시 쓰기 (샘플: ch01-p12)

선생님(원장님)이 샘플 ch01-p12(https://nolbada.github.io/via/eobeop-jedaero/ch01-p12.html)를 보고 "마음에 든다, 나머지도 똑같이"라고 했다. 샘플의 데이터는 `_tools/daily/ch01-p12.json` — 먼저 이 파일 8개 항목을 정독하고 **문체·길이·구성을 그대로 따라라.** 기존 항목 정보는 `_tools/base/<key>.json`(문항·바른문장·해석·배지·기존 해설 포함; groups→items 순서가 곧 작성 순서).

## 할 일
담당 key마다 `_tools/daily/<key>.json` 을 만든다 = **base의 groups→items를 쭉 펼친 순서와 1:1로 대응하는 리스트**. 각 원소는 아래 필드를 모두 가진다.

- `ko`: 자연스러운 해석(문장 하나). base 항목에 `interp`가 있으면 **그대로 복사**, 비어 있으면(지문형 항목) 바른문장(`correct`)을 직접 자연스럽게 해석.
- `dk`: 직독직해 [[영어조각, 한글조각], …]. 영어조각을 이어 붙이면 `correct`(바른문장)와 **띄어쓰기 단위로 정확히 같아야** 한다(검사 스크립트가 확인). 천일문S 본책 끊어읽기 규칙: 긴 주어 뒤, 긴 목적어·보어 앞, 접속사 앞, 긴 부사구 앞뒤에서 끊되 **너무 잘게 쪼개지 말 것**(보통 2~4조각, 긴 문장도 최대 5). 한글은 영어 조각에 맞춰 쓰되 약간 어색해도 된다(자연스러운 해석은 `ko`가 따로 있다). 뼈대·괄호·회색 표시 같은 건 없다.
- `gist`: 한 줄 정리 — "~라는 얘기예요."/"~예요." 로 끝나는 쉬운 한 문장(문장 내용 요약, 문법 설명 X).
- `fm`: 오답노트 공식 — 수학 공식처럼 아주 짧게(예 "A and B (같은 모양)", "핵심 주어 + 동사 (수 일치)", "주어 + 동사 (-ing는 동사가 아니에요)"). 더하기 부분은 " + " 로 쓰면 화면에서 강조된다.
- `mp`: [[칸이름, 쉬운 예 조각, 이번 문장 조각], …] 1~3줄. **쉬운 예 조각과 이번 문장 조각은 크기·모양이 일대일로 같아야** 한다(이번 조각이 구(예: the house surrounded by palm trees)면 쉬운 예도 구(The book written in Japanese)). 이번 문장 조각은 **문법 포인트만 보이게 짧게**(관련 없는 꾸밈말은 뺀다). 쉬운 예는 초등학생도 아는 단어로.
- `ex`/`exko`: 쉬운 예 문장과 그 해석. 해석 안 단어도 어려우면 `단어(뜻)` 형태로 뜻을 붙인다.
- `tko`: **이번 문장 조각만의 해석**(mp에 보이는 조각의 해석이지 문장 전체 해석이 아님).
- `bad`/`badko`: 쉬운 예를 같은 오류로 틀리게 쓴 문장 + 왜 틀렸는지 괄호 한 줄(예 "(boys(소년들)가 여러 명이라서 runs가 아니라 run이어야 해요)").
- `altw`/`alt`/`altko`: 학생이 "고쳐서 쓴 다른 모양"이 아니라, **정답 대신 후보로 헷갈릴 만한 다른 형태(예: -ing, who, which, to 등)가 맞게 쓰이는 초등학생도 아는 쉬운 문장**과 해석. `altw`는 그 형태 이름(예 "closing", "-ing", "who"). 해석 필수. 어울리는 예가 정말 없으면 `alt`를 ""로.
- `why`: "왜 그럴까요" — 초등 6학년에게 짚어 주듯 쉬운 말로 2~4문장. **gist·fm과 내용이 중복되면 안 된다**(gist=내용 요약, fm=공식, why=이유 설명). 동사가 나오면 활용형 그대로 두지 말고 원형(뜻) 병기(예: went → go(가다)). 영어 단어·표현에는 늘 한글 뜻. base의 기존 `explain`이 정답이다 — 모순 금지(다만 더 쉽게 다시 써라).
- `trend`: HTML 문자열 `"<b>출제 N위 · 유형이름</b><br>31년간 M회 나왔어요.<br>한 줄 요령"` 형식. **아래 표에 있는 유형일 때만 순위·횟수를 쓰고**, 표에 없으면 `"<b>출제 순위</b> · 상위 10위 밖 유형이에요.<br>한 줄 요령"`. 숫자를 지어내지 말 것.
  표(어법끝 ESSENTIAL 권두부록, 1994~2025 31개년): 1위 정동사 vs 준동사 113회 / 2위 관계대명사와 관계부사 99회 / 3위 that[which] vs what 71회 / 4위 능동 v-ing vs 수동 p.p.(분사) 70회 / 5위 병렬구조 68회 / 6위 수식받는 주어의 수일치 57회 / 7위 능동태 vs 수동태 52회 / 8위 형용사 자리 vs 부사 자리 50회 / 9위 대명사의 성·수·격 일치 44회 / 10위 목적격보어/준동사 30회.
  매핑 가이드(배지의 Chapter/POINT 기준, 애매하면 "10위 밖"): CH01 POINT1=6위, CH03 POINT1·2=7위, CH03 POINT3=4위, CH07 POINT1=1위, CH07 POINT2=10위, CH07 POINT3·4·5=4위, CH08 전부=5위, CH09 POINT3=3위, CH10 POINT1·2·3=2위, CH10 POINT4=3위, CH11 POINT1~4=9위, CH12 POINT1·2·3=8위. 그 밖(CH02·04·05·06·13·14, CH01 나머지, CH09 POINT1·2, CH10 POINT5, CH11 POINT5, CH12 POINT4·5)은 10위 밖. 단 오류가 "-ing/p.p./to V를 문장의 진짜 동사 자리에 썼거나 그 반대"인 경우는 배지와 상관없이 1위(정동사 vs 준동사)로 써도 된다.
- `d`: 문제 문장 속 영어 단어 뜻 사전(학생이 단어를 누르면 보임). 키는 **소문자 단어**, 값은 이 문장에서 쓰인 뜻(활용형이면 "play(놀다)의 -ing형"처럼 원형(뜻)). 쉬운 기초 단어(the, is, a 등)는 빼도 되나 **학생이 모를 만한 단어는 전부**(오류 표현에 쓰인 단어 포함, 문장 속 단어 전부 권장). 숙어는 대표 단어 키에 "a lot of: 많은" 식으로(콜론 앞이 숙어). 뜻은 문장에서 쓰인 의미에 가장 맞는 것(예: novel이 '새로운'이면 '소설' X).

## 문체 규칙(선생님이 꼭 지키라고 한 것)
- 초등 6학년에게 짚어 주듯 쉬운 한국어. 짧게. 사전식 어원·품사 설명 금지.
- **이모지·특수 아이콘 금지.** 학생 화면이다.
- 영어가 나오면 반드시 한글 뜻. 해설 속 예로 드는 단어도 `단어(뜻)`.
- 오답노트 칸(fm/mp/ex…)은 길어지지 않게. 쉬운 예와 이번 문장 사이에 구조 차이가 있으면 `badko`나 `why`에 짧은 부연.
- 수동태·분사 문장 등 문장 분석이 필요한 곳은 base의 기존 해설과 같은 결론이어야 한다.
- 문장 자체가 변형으로 어색해도 바른문장을 그대로 쓴다(고치지 말 것).

## 절차
1. 담당 key 하나씩 `_tools/base/<key>.json` 을 읽고 `_tools/daily/<key>.json` 작성(JSON, UTF-8, 들여쓰기 자유).
2. `cd /home/claude/via/eobeop-jedaero && python3 _tools/check_daily.py <key>` → OK가 될 때까지 고친다.
3. `python3 _tools/gen_daily.py <key>` 로 페이지 생성(자기 key만). **`build_daily.sh`·`gc.py`는 돌리지 말 것**(다른 에이전트와 충돌). git 금지. 담당 외 파일 수정 금지.
4. 끝나면 짧게 보고: 페이지·항목 수, 애매한 항목(오류 판정 불분명, 순위 매핑이 애매한 항목 등).
정확성 최우선: 바른문장 문법, 직독직해 대응, 쉬운 예가 정말 같은 구조인지, 번역 오류 없는지 스스로 한 번 전수 검산한 뒤 보고.
