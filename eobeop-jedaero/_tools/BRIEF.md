# 작업 지시 (문장 분석 + ✍노트정리 추가)

대상: /home/claude/via/eobeop-jedaero/ 의 해설 페이지 chNN-pXX.html (담당 챕터 파일 전부).
각 페이지의 `<p class="answerline">`(오류 하나) 마다 분석 1개를 만든다. JSON 리스트 길이 = 그 페이지의 answerline 수, 문서 순서대로.
- 문장 카드(문항 1개=오류 1개): 분석 대상 = '바른문장'.
- 지문 카드(오류 여러 개): 각 answerline이 가리키는 오류가 들어 있는 '바른 지문'의 그 문장 하나를 분석 (오류 단어 → 정답으로 고친 문장).
같은 문장에 오류가 둘이면 둘 다 각각 분석 항목을 만들되 notes는 각자의 포인트로 다르게.

JSON 항목 형식 (샘플: /home/claude/via/eobeop-jedaero/_tools/sample_item.json):
{"en":"바른 영어 문장, 뼈대 단어를 [[ ]]로 감싼다 (예: A number of [[movies]] today [[feature]] [[digital special effects]].)",
 "key":"뼈대 한 줄 한글 (예: 영화들이 특수효과를 특징으로 한다.)",
 "form":"1형식|2형식|3형식|4형식|5형식",
 "ref":[닮은꼴 5문형 칩], "refrel":"관계",
 "me":[["문장 덩어리","s|v|o|c|io|do|oc|x"],...], "merel":"관계(예: movies ≠ effects / he = tired)",
 "easy":[["먼저 뼈대부터:","영어 뼈대","한글"],["어떤 ~?","영어 덩어리","한글"],...,["한 줄 요약(한글)"]],
 "notes":["<b>핵심</b> 한 줄", ...]}

닮은꼴 ref/refrel 고정값:
1형식 [["I","s"],["sleep","v"]] ""
2형식 [["I","s"],["am","v"],["happy","c"]] "I = happy"
3형식 [["I","s"],["like","v"],["apples","o"]] "I ≠ apples"
4형식 [["I","s"],["give","v"],["him","io"],["a book","do"]] "him ≠ a book"
5형식 [["I","s"],["make","v"],["him","o"],["happy","oc"]] "him = happy"
me 칩은 문장 전체를 순서대로 빠짐없이 덮는다(그대로 이어 붙이면 원문). 꾸미는 말/부사구/접속사절은 "x"(덧붙는 말) 또는 주어·목적어 안에 포함. 종속절·준동사가 길면 한 칩으로 묶고 풀어보기에서 풀어 준다. 문장이 둘 이상의 절이면 주절 기준으로 형식을 쓰고, easy에서 절을 하나씩 풀어 준다. 접속사로 이어진 문장의 형식은 주절 기준.

문체 규칙(학생용, 아주 중요):
- 초등 6학년에게 짚어 주듯 쉬운 한국어. 짧게. 사전식 어원/품사 설명 금지.
- 영어가 나오면 반드시 한글 뜻 병기. 동사는 활용형 그대로 두지 말고 원형+한글 뜻 (예: went → go(가다)).
- easy: 3~5줄. 뼈대 → 덩어리별로 "어떤 ~?" → 마지막 요약 1줄(길이 1 배열). 한글은 직독직해 순서에 맞는 자연스러운 해석.
- notes: 2~3개(많아도 4). 이 문항의 어법 포인트(해설의 POINT)를 원칙+예시로 한 줄씩, 그리고 문장 뼈대에서 건질 한 가지(주어 찾기, 형식, 수식 관계 등). <b></b>만 사용. 학생이 노트에 한 번 쓸 가치가 있는 것만.
- 해설(explain) 내용과 모순되면 안 됨. 해설이 맞다. 정확성이 최우선(영문법 틀린 말 금지, 모르면 단정 말고 단순하게).
- 문장이 이미 구성 요소를 바꿔 쓴 변형이라 어색해도 바른문장을 그대로 분석(원문 고치지 말 것).
